# TalAI

Учёт деревьев, планирование посадок и история обследований.

Локальный MVP на React + Vite + Node.js 22.13+ (встроенный SQLite). Существующая интеграция MapGL 2ГИС сохранена.

## Запуск

```bash
npm ci
# .env.local: VITE_2GIS_API_KEY=ваш_ключ
npm run dev -- --port 5174
```

Приложение: http://127.0.0.1:5174. Сервер слушает loopback. Ключ должен иметь доступ к Map Tiles API и разрешать используемый origin. Ключ не включён в репозиторий.

```bash
npm run build
node --import tsx server.mjs --production --port 5174
```

`npm run dev` теперь запускает также API, а не отдельный Vite без хранения. Переменная `TALAI_DATA_DIR` задаёт каталог данных; по умолчанию `storage/`. Node может выводить предупреждение об экспериментальном `node:sqlite`.

## Что изменилось

Раньше действующая карта показывала HTML-маркеры поверх декоративных деревьев 2ГИС. Отдельные старые Three.js-компоненты существовали в коде, но GLB/glTF-плагин в карте не использовался. В географическом демонаборе находилась искусственная сетка из 60 объектов, состояние хранилось только в localStorage.

Теперь:

- Участок «Ботанический сад — центральный участок» ограничен географическим полигоном в северной части центрального круга, вокруг открытого треугольного газона. Контур и начальная камера заданы в `src/territory.ts`. Выбор сделан по текущей карте; это не кадастровая граница.
- Четыре отдельные демонстрационные точки размечены вручную по изображениям крон базовой карты. Источник: «Демонстрационная разметка по базовой карте». Порода и состояние не предполагаются; подтверждения на местности нет.
- Десять будущих деревьев расположены по дуге открытого газона с равным интервалом около 4,1 м. Пригодность места для посадки не установлена. Высота 4 м и крона 2,5 м — проектные параметры, не прогноз роста.
- `public/models/talai-tree.glb` — собственная модель с ветвями и неоднородной кроной, созданная `scripts/create-tree.mjs`. Внешние модели, изображения и тайлы для её создания не извлекались. Встроенные геометрии Three.js, собственная композиция; пользователь проекта может изменять и использовать модель.
- Модели добавляются официальным `@2gis/mapgl-gltf` v2, имеют собственные ID, выбираются кликом, перемещаются по карте или координатами, редактируются и удаляются. Слой «Будущие посадки» управляет моделями и вспомогательными знаками 2D независимо от подложки.
- История: территория → участок → обследование → оригинальные материалы, отдельные превью и результаты. Выбор даты не подменяет отсутствующие материалы другой датой. Сравнение A/B использует синхронизированные карты и отдельные галереи.

## География и 2ГИС

В API карты и glTF-плагина всегда `[longitude, latitude]`. В записи БД поля именованные. Метрическое размещение вычисляется относительно географического центра через `ringPoint`; поворот камеры координаты не меняет. В 2D и 3D используются одни и те же координаты основания. GLB имеет стандартную Y-up ориентацию: дополнительный rotateX не нужен. Клик плагина дополнен небольшим экранным допуском вокруг кроны только для собственных моделей TalAI (для небольших моделей и программного WebGL). Высота/крона меняют масштаб узла GLB; основание остаётся на нулевой высоте.

Старые `coord`/`XY` оставлены для старого локального проекта с прежним ORIGIN. Эти данные НЕ геопривязаны к саду. Они не поворачиваются и не сдвигаются автоматически, пользовательские координаты не подгоняются под графику карты. Неизменённая синтетика исключена из активного набора. Изменённые/пользовательские записи сохраняют координаты, даже если они за пределами нового участка.

Проверены официальные документы:

- [glTF-плагин v2](https://docs.2gis.com/mapgl/objects/gltf2-plugin): собственные модели, координаты, клики, показ и скрытие.
- [Деревья на карте](https://docs.2gis.com/mapgl/map-style/immersive/trees): декоративные модели и возможность рандомизации размера, поворота и смещения.
- [Выделение объектов](https://docs.2gis.com/mapgl/objects/selection): `click.target.id` у доступных объектов карты. Это не обещание каталога каждого декоративного дерева.

Документированный способ получить полный перечень отдельных декоративных деревьев выбранной зоны с устойчивыми ID и координатами не найден. Поэтому TalAI использует ручные точки. Координата клика не выдаётся за координату ствола. Автоматическое распознавание и связывание с декоративными деревьями не реализованы. Для реального реестра предусмотрены источники «Съёмка с дрона» и «Наземное обследование».

## Хранение и перенос старых данных

- `storage/talai.sqlite`: таблицы проектов, территорий, деревьев, обследований, наблюдений, архивов и файлов; транзакционное сохранение. Записи таблиц содержат JSON-метаданные, не бинарные фотографии/GLB. Проектный снимок хранит задачи, сценарий и совместимый формат экспорта.
- `storage/uploads/`: оригиналы; уменьшенные WebP-превью хранятся отдельными файлами. В записях — URL, имя, MIME, размер, время загрузки и вид материала. Оригиналы не изменяются.
- Старые ключи `greenwatch.project.v1` и `greenwatch.project.astana.v2` остаются на месте. Они архивируются на сервере; миграция по хешу не повторяется. Пользовательские записи переносятся даже при существующем серверном проекте. При конфликте отличающихся записей сохраняются обе с суффиксом импорта и исправленными ссылками.
- Неизменённая сетка: `public/data/synthetic-grid.json`. Старый локальный набор: `public/data/legacy-demo.json`. В интерфейсе «Данные и отчёты» доступен экспорт старого браузерного проекта, если он есть; иначе — архива сетки.
- Новый ключ `talai.project.v3` — локальная копия метаданных. Старые встроенные фотографии активных записей переносятся в файлы при миграции. Исходные браузерные ключи остаются неизменными для сохранности; в серверном архиве фотографии представлены ссылками на сохранённые оригиналы.

Резервируйте **весь каталог storage**, включая SQLite и uploads. Для согласованной файловой копии остановите сервер или используйте SQLite backup. JSON-экспорт содержит ссылки на серверные файлы, не является самостоятельным архивом медиа.

## Обследования и история

Обследование хранит ID, участок, точную дату, отдельное фактическое время съёмки (`captureAt`) и время загрузки (`uploadedAt`), источник, описание, статус, признак демо и материалы. Статусы: запланировано, загружено, обрабатывается, готово, ошибка. Сезон — дополнительная подпись.

Начальные сентябрьская и декабрьская записи — демонстрационный план, без материалов и без подтверждённого времени съёмки. Декабрь 2026 на дату разработки находится в будущем. Загрузка требует прошедшего фактического времени съёмки. Сервер запрещает будущую съёмку с завершённым статусом или материалами.

Загрузить можно RGB, тепловые файлы, ортофотоплан, модель участка и внешние результаты обнаружения. Никакая загрузка сама по себе не создаёт деревья, измерения, диагнозы или реконструкцию. Интерфейс сообщает: «Материалы загружены, обработка не подключена».

PNG/JPEG/WebP ортофотоплан с подтверждёнными WGS84-границами запад/юг/восток/север отображается через официальный Raster. Это режим для ориентированного на север растра; произвольные проекции и повёрнутые ортофото требуют предварительной подготовки. Обычные фотографии показываются только в галерее. TIFF хранится как оригинал для скачивания, без браузерной конвертации. GLB участка можно вручную геопривязать координатами и масштабом; без привязки он только доступен для скачивания. Для glTF необходим самодостаточный файл; загрузка пакетов внешних текстур/BIN пока не реализована.

Дерево — постоянная запись; наблюдения ссылаются на обследование и имеют собственные дату, источник, способ оценки, статус, заметку, возможные измерения и фото. Создание точки не создаёт фиктивного наблюдения. Наблюдение новой даты добавляется отдельно. Карточка выбранной даты не показывает будущие наблюдения как прошлые. Основные фотографии зоны не размножаются по деревьям.

## Проверки

```bash
npm test
node --import tsx scripts/check-domain.mjs
node --import tsx scripts/storage-check.mjs
node scripts/browser-check.mjs
```

Последние две команды открывают локальные порты; браузерный сценарий использует `/usr/bin/google-chrome`, отдельную временную SQLite и реальный 2ГИС, а не макет SDK. Ему нужен доступ к сети. `screenshots/talai-*.png` — результаты проверки; тестовая загрузка является явно помеченным скриншотом интерфейса, не аэрофотосъёмкой. Тестовые данные не попадают в основной серверный каталог.

Локальный MVP не содержит авторизации, многопользовательского разрешения конфликтов, очереди фотограмметрии или фонового CV-процессинга. Переключение демонстрационной роли не является защитой доступа. Серверная ошибка сохранения показывается пользователю; локальная копия позволяет экспортировать изменения, но не гарантирует автоматическое восстановление несохранённых сервером правок.

Итоговая проверка 12 октября 2026: сборка успешна; 10 модульных проверок; 3 Playwright-проверки (включая перенос старой фотографии и идемпотентную миграцию); отдельный тест остановки/повторного запуска SQLite и сохранности байтов оригинала. Полный сценарий с реальным 2ГИС прошёл: 10 GLB, выбор кликом, слой, вращение, перемещение, размеры, удаление, перезагрузка, загрузка/превью, изоляция дат и сравнение галерей, без ошибок JavaScript. Машиночитаемые результаты: `screenshots/browser-results.json`, `screenshots/history-results.json`. Реальных геопривязанных материалов для проверки ортофотопланов и модели обследованного участка не предоставлено; их обработка и реконструкция не имитировались.
